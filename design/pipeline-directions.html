Offer Desk · dashboard direction

Where the pipeline stands, as a report

Four ways to rebuild the dashboard so a laptop screen earns its width and the pipeline panel reads like a report instead of a list of colored tags. All four share the same desktop shell — a fixed left rail, a KPI strip, a real content grid — so the choice below is about how the pipeline itself is drawn, not about the chrome.

Same numbers in every frame: 40 deals logged, 32 offers sent, 19 live, 13 answered, 4 accepted. Pick one and I'll build it.

A

The funnel

The pipeline is a conversion problem, so draw it as one. Every stage shows how many survived, what it's worth, and the rate at which it feeds the next stage. Where deals leave is annotated between the bars — that's the number that tells you which part of your process is broken.

B

The ledger

A real table, the way an operator reads a P&L. Stages grouped into live, answered and dead, with subtotals; every number right-aligned in tabular figures so the columns actually line up. The share column carries an inline bar, so it scans like a chart without becoming one. Aging is the column that does the work — a 16-day-old follow up is flagged in the row, not buried.

C

Two questions

There are only two things you actually ask this screen: what's on my desk right now, and are my offers landing. So the panel splits in half and answers one on each side. The left half ages the live deals so the stalled ones surface themselves; the right half turns win rate into a headline with the trend under it. Underneath, the four deals that need a call today.
